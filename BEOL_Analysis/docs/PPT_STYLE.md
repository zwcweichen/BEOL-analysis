# 戰報 PPT 設計語言公版（v3.3 草案）

來源：使用者提供的四張工程簡報（Rs results／Rs 拉回中間／Rc trace／Yield lot CP check）觀察歸納，加上 academic-pptx-skill 的通則（白底、少色、無裝飾、結論先行）。公司商標、版權列、機密分級不納入。

## 0. v3.6 增補

- K 表寬度依內容估算（CJK 1.0 em、英數 0.7 em），名稱欄／數值欄各自配寬；總覽格內上限半格寬，放不下時先去片數後綴再縮字（最小 7pt），不蓋圖。
- 單張圖（1×1／1×2 格、HL 細節）PNG 以格子的實際寬高比重畫（1.8–3.2），貼圖同比例，不拉伸。
- 封面不放來源檔名小字。

## 0.1 v3.5 增補

- 摘要列只寫「組 CIP　item 偏移、item 偏移」，不寫燈號計數、期間、分組、片數；偏移量一位小數。片數只出現在點燈表格子下方小字（fs−2.5、7F7F7F）與封面條件表。
- 小模組（摘要＋點燈表＋HL 總表 ≤ 7.0 in）合成一頁。封面每模組一條摘要列，續行縮排不加紅點，最多 6 列。
- HL 細節 trend／相關圖 PNG 比例 1050:400（圖寬 5.5 in）。

## 1. 頁面骨架（16:9，13.33 × 7.5 in）

| 區域 | 位置 | 規則 |

| 區塊標題 | 各區塊左上 | 藍色空心方塊 ☐ ＋ 藍色粗體底線 14pt，格式「圖名 ｜ 條件／組」。取代原本灰色小字 a／b 標籤。 |

## 2. 圖與數字的關係

- **數字是讀法，圖是證據**：每張 trend 圖左側貼一個 K 小表（每條件一列，條件名用條件色，數值用燈號色：橘 `C00000`、黃 `B8860B`、綠 `2E7D32`）。BSL 列灰字寫 `BSL` 或 `n 653`。圖本身不放 Plotly 圖例。
- 條件色固定全冊：BSL 灰 `7B8694`（點小、半透明），CIP 依序藍 `1F3FBF`、橘 `E8590C`、青 `0F9D8A`、紫 `B5179E`（點大、實心、白邊）。
- 圖的寬高比 9:4（trend）或 1:1（相關圖）；圖內字 12–13pt（匯出時用 scale 2 重畫，不是網頁截圖縮放）。
- 總覽 trend：異常 item 每組一頁，格數自適應（1 個 → 1×1、2 個 → 1×2、3–4 個 → 2×2；格高上限 4.2／3.4 in；PNG 寬度隨格寬放大）；綠燈 item 跨組合併成 3×3 附錄（cell = item × 組），超過 9 格分頁。K 表寬 1.55／1.3 in，列高 min(0.27, (格高−0.36)/列數)。
- 相關圖：灰點 BSL、彩點 CIP、各條件一條回歸線；K 表寫「有關聯／關聯弱／未偏移」而不是 r。

## 3. 文字

- 字型：中文 Microsoft JhengHei、數字與英文 Arial；全冊一種粗細層級（標題 26 / 摘要 13 / 區塊標題 14 / 內文 12 / 表 11 / K 表 10）。
- 建議檢查列：✔ 黑粗體、✘ 灰 `8C8C8C`、○ 深灰；一列一句「對象　偏移量　判定」，不加括號解釋。
- 不用卡片底色、不用裝飾線、不用圖示；右欄只用區塊標題分段。
- 「同組其他 item」小表：同一組其他 WAT／yield 的偏移量，讓讀者不用翻頁就知道這個 HL 是否孤立。

## 4. 頁序

封面（條件、期間、N、燈號計數）→ 點燈表 → HL 總表 → HL 細節（每個橘燈一頁，黃燈視設定）→ 總覽 trend 2×2（異常）→ 3×3 附錄（綠燈）→ **結論頁**（燈號計數、前三個 HL、共同的建議檢查）。不以 Thank you 或 trend 矩陣結尾。

## 5. 三角色內審（對這份公版）

- **A 開發**：與現有 `buildPpt` 的差異在（1）標題只寫現象、（2）摘要列取代卡片、（3）K 表取代圖例、（4）2×2／3×3 分流、（5）結論頁。圖要在匯出時以 PPT 字級重畫，`figPng` 傳入字級與邊距。
- **B 使用者**：工程師先看摘要列的藍字，再看 K 表，圖只在數字可疑時細看——所以 3×3 可以小，但 K 表一定要清楚；條件色全冊固定才不用每頁找圖例。
- **C 體驗／管理者**：參考簡報的缺點不要抄——x 軸 lot 名字糊成一片（改用 wafer 順序，軸標題寫排序依據）、一頁五種顏色（我們最多 BSL＋2 個 CIP 一頁）、截圖解析度低（向量重畫）。底線：一頁只回答一個問題，標題就是答案。
